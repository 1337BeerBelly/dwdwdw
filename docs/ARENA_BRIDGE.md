# Обмен файлами с чатом Arena

Как вместе со мной (Arena Agent Mode) работать над проектом, который лежит у вас на компьютере.

Коротко: вы упаковываете проект одним батником, прикладываете архив в чат, я правлю файлы и возвращаю архив, а второй батник раскладывает правки обратно — с бэкапом и проверкой по хешам.

```
       ваш компьютер                                  чат Arena
 ┌────────────────────────┐                   ┌────────────────────────┐
 │  проект (папка)        │  arena-pack.bat   │  я распаковываю архив, │
 │  → project-pack-*.zip  │ ────────────────► │  правлю файлы,         │
 │                        │   вы прикладываете│  собираю ответ         │
 │  arena-unpack.bat      │ ◄──────────────── │  project-pack-reply.zip│
 │  ← правки + бэкап      │   вы скачиваете   │                        │
 └────────────────────────┘                   └────────────────────────┘
```

---

## Вариант А (проще всего): проект уже в GitHub

Если ваши файлы лежат в репозитории GitHub, архивы не нужны вообще:

1. Скажите мне ссылку на репозиторий и над какой веткой работать.
2. Я правлю файлы и коммичу в отдельную ветку.
3. Вы забираете изменения у себя: `git pull`.

Плюсы: полная история, ничего не надо пересылать, легко откатывать. Минус: файлы должны быть в репозитории (секреты — в `.gitignore`, как обычно).

## Вариант Б: обмен архивами (для любой папки)

### Требования

- Node.js 18+ (у вас он уже есть, если ставили `freeclaude` — версия 22).
- Windows: `arena-pack.bat` / `arena-unpack.bat`.
  macOS/Linux: `arena-pack.sh` / `arena-unpack.sh` (то же самое).

### Шаг 1. Упаковать проект

Двойной щелчок по `arena-pack.bat` — он спросит папку (её можно просто перетащить в окно консоли). Либо перетащите папку проекта прямо на файл `arena-pack.bat`, либо из терминала:

```
arena-pack C:\dev\my-app
```

Дальше батник спросит, что нужно сделать, и это уедет в архив (`_ARENA/REQUEST.txt`).

Что попадёт в архив:

- все текстовые файлы проекта: исходники, конфиги, документация, скрипты;
- файлы размером до 5 МБ каждый;
- картинки и шрифты (тоже до 5 МБ).

Что вырезается автоматически (и это печатается в отчёте):

| Что | Почему |
| --- | --- |
| `.git`, `node_modules`, `dist`, `build`, `.venv`, `__pycache__`, `.next`, `bin`, `obj`, `target`, `coverage`, `.idea`, `.vs` и подобные | служебные и генерируемые папки — раздувают архив и мне не нужны |
| `.env`, `*.pem`, `*.key`, `id_rsa*`, `credentials.json`, `secrets.json`, `.npmrc`, `.netrc` и др. | **секреты**: в архив-отправление они не попадают (`.env.example` при этом остаётся) |
| файлы больше 5 МБ | лимит на файл, меняется флагом `--max` |
| `.zip`, `.exe`, `.dll`, `.sqlite`, видео и прочие бинарники | не текстовые данные, мне они не помогают |

Полезные флаги:

```
arena-pack C:\dev\my-app --include src,docs        только эти папки (фильтры отключаются)
arena-pack C:\dev\my-app --max 20                  лимит на файл 20 МБ (--max 0 — без лимита)
arena-pack C:\dev\my-app --all                     всё, кроме .git и мусора ОС (секреты всё равно вырезаются)
arena-pack C:\dev\my-app --with-secrets            не вырезать секреты — только осознанно!
arena-pack C:\dev\my-app --dry-run                 посмотреть, что попадёт, и ничего не создавать
arena-pack C:\dev\my-app --out D:\обмен --clip     куда положить архив и скопировать текст для чата
```

Архив по умолчанию кладётся на Рабочий стол с именем `<проект>-<дата-время>.zip`.

### Шаг 2. Отправить в чат

Перетащите архив в окно чата и напишите задачу словами. Задача, введённая на шаге 1, уже лежит внутри архива — мне её видно.

### Шаг 3. Что делаю я

1. Распаковываю архив в своей песочнице (файлы лежат в корне, служебное — в `_ARENA/`).
2. Правлю файлы, при необходимости запускаю сборку/тесты.
3. Собираю ответный архив: только изменённые и новые файлы + `_ARENA/CHANGES.txt` (что и почему сделано) + `_ARENA/DELETED.txt`, если что-то удалено.
4. Отдаю архив вам: открываю его в просмотрщике файлов или выкладываю в приватный репозиторий GitHub и даю ссылку — смотря что удобнее в вашей ситуации.

### Шаг 4. Разложить правки

Перетащите полученный zip на `arena-unpack.bat` — или из терминала:

```
arena-unpack reply.zip --into C:\dev\my-app
arena-unpack reply.zip --dry-run            сначала посмотреть план
```

Что происходит:

1. Проверяется, что это действительно ответный архив (в нём есть `_ARENA/CHANGES.txt`). Свой собственный архив-отправление распознаётся и не раскладывается.
2. По SHA-256 вычисляется, что изменилось, что новое, что удалено, — печатается план.
3. Затрагиваемые файлы копируются в `<проект>\_arena_backup\<имя-пакета>\`.
4. Новые и изменённые файлы записываются, удалённые переносятся в бэкап.
5. Печатается `CHANGES.txt` — что именно я сделал.

Папку проекта батник берёт из архива (путь, где вы его собирали). Если папка переехала — укажите `--into`, а `--here` разложит в текущую.

Откат: скопируйте файлы из `_arena_backup\<пакет>\` обратно. Если проект в git, дополнительно видно `git status` и `git diff`.

## Формат архива

```
<файлы проекта в корне архива>
_ARENA/INFO.txt        ключ=значение: имя проекта, путь, дата, режим, счётчики, git-ветка
_ARENA/MANIFEST.txt    sha256, размер и путь для каждого файла
_ARENA/REQUEST.txt     задача, которую вы ввели при упаковке (если вводили)
```

Ответный архив отличается только служебными файлами:

```
<изменённые и новые файлы в корне>
_ARENA/CHANGES.txt     описание правок
_ARENA/DELETED.txt     что удалить (строки-пути), если было
_ARENA/INFO.txt        копия исходного INFO + поля REPLY_FOR, REPLIED_AT, счётчики
```

Архивы обычные (ZIP, методы store/deflate, UTF-8 имена) — открываются Проводником Windows, `unzip`, 7-Zip и Python `zipfile`. Если прислать мне архив, собранный другим инструментом, он тоже читается: `arena-unpack --force` разложит даже zip без служебной папки `_ARENA`.

## Частые вопросы

**«Он говорит, что изменений нет».** Значит, файлы в архиве совпадают с текущими по хешу. Возможно, правки уже разложены ранее, или архив не тот.

**«Секреты точно не уезжают?»** Любой фильтр можно обойти ошибкой в имени файла, поэтому: не держите ключи в текстовых файлах проекта, а если сомневаетесь — сначала `--dry-run` и прочитайте отчёт (он печатает каждое исключение). Батник вырезает типовые секреты, но не заменяет `.gitignore` и здравый смысл.

**«Проект огромный, архив не влезает в чат».** Сузьте выборку: `--include src,docs` или `--max 2`. Отправьте ту часть, где лежит задача.

**«Длинные пути».** Файлы с полным путём длиннее 250 символов пропускаются (об этом пишется в отчёте) — Windows-ограничение на разумной длине пути. Перенесите проект ближе к корню диска, например `C:\dev\...`.

**«Почему нужен Node.js?»** Инструменты написаны на нём: один и тот же код работает на Windows, macOS и Linux, а главное — он протестирован целиком, включая упаковку, чтение и раскладку архивов (`node tests/roundtrip.mjs`).

**«А можно, чтобы я просто дал папку, а вы работали в ней напрямую?»** Нет: я работаю в изолированной облачной песочнице и доступа к вашему диску не имею. Именно поэтому есть этот обмен — либо вариант с GitHub выше.
