# Kiro: портал авторизации не открывается

Что делать, если при подключении провайдера Kiro в OmniRoute не открывается страница входа (портал Kiro или страница AWS Builder ID), либо вход открылся, но не завершается.

Начинайте с диагностики — она покажет, что именно недоступно **у вас**:

```
kiro-check
kiro-check --json > kiro-check.json     вывод в файл, удобно прислать в чат
```

Скрипт проверяет DNS и HTTPS до всех доменов, задействованных во входе, состояние шлюза, прокси, файл `hosts` и точность системных часов. В конце — «Диагноз» с конкретными следующими шагами.

---

## 1. Главное: портал не обязан открываться на том же компьютере

Вход в Kiro (и через Builder ID, и через Google/GitHub) построен на **device-code**: дашборд показывает **код** и **ссылку**, а сам шлюз опрашивает Kiro/AWS и ждёт подтверждения.

Поэтому:

1. Нажмите в окне авторизации кнопку копирования ссылки (или просто выделите и скопируйте её).
2. Откройте ссылку **на телефоне** — лучше по мобильному интернету, а не по Wi-Fi.
3. Введите там код с экрана компьютера и подтвердите вход.
4. Вернитесь к окну OmniRoute: оно само увидит подтверждение и завершит подключение.

Это обходит почти все локальные причины: DNS-фильтры провайдера, корпоративный VPN, блокировки в браузере и антивирусе.

**Сколько есть времени:** код живёт около 5 минут (точное значение приходит от сервиса). Не успели — закройте окно и начните заново.

---

## 2. Какой именно способ подключения у вас

В **Dashboard → Providers → Kiro** доступны несколько способов — они используют разные домены, поэтому «не работает один» ≠ «не работает Kiro»:

| Способ | Что откроется | Если домен недоступен |
| --- | --- | --- |
| **Device Code** (AWS Builder ID / IDC) | страница AWS `view.awsapps.com` | переключитесь на вход через Google/GitHub |
| **Google / GitHub** | портал входа Kiro `prod.us-east-1.auth.desktop.kiro.dev` | используйте Device Code, Auto-Import, Import Token или API Key |
| **Auto-Import** | ничего не открывается | читает данные из Kiro CLI / IDE — портал не нужен вообще |
| **Import Token** | ничего не открывается | вставляется refresh-токен вручную |
| **API Key** | ничего не открывается | вставляется долгоживущий ключ |

Из CLI тот же вход доступен так (шлюз должен быть запущен):

```
omniroute oauth start --provider kiro --social google --no-browser   # или --social github
omniroute oauth start --provider kiro --import-from-system           # авто-импорт из Kiro CLI
```

`--no-browser` печатает ссылку и код в консоль — удобно, когда браузер на этой машине не работает.

## 3. Портал или страница AWS не открывается

Проверяйте по порядку (останавливайтесь на том, что помогло):

1. **Режим инкогнито.** Так делает и само окно OmniRoute — там прямая подсказка. В обычном профиле мешают кэш, расширения и блокировка сторонних cookie.
2. **Отключите блокировщики и фильтры**: расширения-адблоки, антивирусный веб-щит, AdGuard / Pi-hole, DNS-фильтры роутера. Частая причина — домены `amazonaws.com`, `awsapps.com`, `kiro.dev` в чёрных списках.
3. **Другой браузер.** Если открывается в другом — виноват профиль/расширения первого.
4. **Другая сеть.** Телефон в режиме модема или мобильный интернет. Если там открывается — проблема на уровне вашей сети/провайдера/VPN.
5. **DNS.** Смените на `1.1.1.1` / `8.8.8.8` или включите DNS-over-HTTPS. Проверьте файл `hosts` (`C:\Windows\System32\drivers\etc\hosts`) — там не должно быть записей для этих доменов.
6. **VPN.** Включите (если портал недоступен из вашей сети/региона) или, наоборот, **выключите** — корпоративные VPN часто режут сторонние домены и подменяют сертификаты.
7. **Прокси.** Если заданы `HTTP_PROXY`/`HTTPS_PROXY` или системный прокси, шлюз пойдёт за токенами через него. Убедитесь, что он пропускает `*.amazonaws.com`, `*.awsapps.com`, `*.kiro.dev`. Прокси для конкретного подключения задаётся в **Dashboard → Settings → Proxies**.
8. **Часы системы.** При расхождении больше пары минут device-code не сработает — включите автоматическую синхронизацию времени.
9. **Статусы сервисов.** Если недоступен сам сервис (а не ваша сеть) — проверьте страницы статуса Kiro и AWS, проблема может быть на их стороне.

## 4. Портал открылся, но вход не завершается

| Что видите | Причина и что делать |
| --- | --- |
| Окно «Authorization expired» / истёк код | Код живёт ~5 минут. Закройте окно и начните подключение заново. |
| Ошибка после выбора аккаунта | Выберите правильный аккаунт (в ссылке есть `prompt=select_account`). Проверьте, что у аккаунта есть доступ к Kiro. |
| Ничего не происходит, «Ожидание…» бесконечно | Смотрите логи шлюза: `omniroute logs`. Если шлюз не может дойти до Kiro/AWS, вход будет висеть — вернитесь к разделу 3. |
| «Failed to start authorization» / 4xx, 5xx | Повторите позже; проверьте, что шлюз запущен (`omniroute health`) и что у него есть интернет. |
| Успех на портале, но подключения нет | Обновите страницу **Providers**; проверьте список: `omniroute providers status`. Если подключение есть, но не работает — тест соединения в дашборде. |

## 4.1. Ошибка «Connection Failed / invalid_token_response»

Эта строка — **не ответ Kiro**, а сообщение самого OmniRoute (`src/lib/oauth/kiroSocialPoll.ts`). Оно печатается, когда опрос входа вернул HTTP 2xx, но в теле нет ни токенов, ни пометки «ещё ждём» (`authorization_pending` / `slow_down`). Проще говоря: сервер спросил «уже подтвердили?» и не понял ответ.

Почему «не успеваю ничего сделать»: первый опрос уходит примерно через 5 секунд после открытия окна (интервал задаёт сам Kiro). Если он сразу такой — окно падает с ошибкой до того, как вы успеете открыть ссылку и ввести код. Приложения это не касается — это про формат ответа, который не совпал с ожиданием.

**Порядок действий:**

1. **Проверьте версию:** `omniroute --version`. Если меньше **3.8.50** — обновитесь: `npm install -g omniroute@latest`. В 3.8.50 добавили обработку поля `status` для состояния «ждём»; до этого такой ответ как раз превращался в `invalid_token_response`. Актуальная версия — 3.8.51.
2. **Посмотрите сырые ответы Kiro:** `kiro-check --probe-kiro`. Инструмент повторит те же два запроса, что делает OmniRoute (попросит device-код и один раз его опросит), и покажет статус, тип содержимого и тело ответа. Как читать:
   - **опрос отвечает «ждём»** — связь в порядке, а ошибка была из-за конкретного кода: он истёк (~5 минут) или уже использован. Начните подключение заново и подтверждайте вход сразу;
   - **опрос даёт 2xx без токенов и без пометки** — формат ответа не совпадает с ожидаемым: обновитесь и повторите, а если не помогло — подключайте Kiro другим способом (ниже) и приложите вывод в issue проекта;
   - **ответ не JSON (HTML, текст)** — в цепочку вмешался прокси, антивирус с HTTPS-инспекцией или фильтр провайдера. Уберите вмешательство или задайте прокси в **Dashboard → Settings → Proxies**.

   Проба делает два настоящих запроса к Kiro, ничего не подтверждает и код не использует — код живёт ~5 минут и истекает сам. Другой вариант логина: `kiro-check --probe-kiro --login-provider github`.
3. **Подключите Kiro другим способом** — все в **Dashboard → Providers → Kiro**:
   - **Device Code (AWS Builder ID)** — здесь работает другой код и другие домены (`oidc.us-east-1.amazonaws.com`, `view.awsapps.com`), и эта ошибка в принципе невозможна;
   - **Auto-Import** — вход не нужен, если Kiro CLI/IDE уже настроен;
   - **Import Token** — подставьте refresh-токен (`aorAAAAAG…`);
   - **API Key** — долгоживущий ключ, OAuth не используется.
4. **Соберите отчёт:** `kiro-check --probe-kiro --json > kiro-check.json` (и при желании `omniroute logs > logs.txt`). Этого достаточно, чтобы причину нашли в проекте.

**Что проверить попутно:** прокси и антивирусный веб-щит (именно они дают «не-JSON»), системное время (для входа по коду оно критично), отсутствие посторонних записей этих доменов в `hosts`.

## 5. Способы подключить Kiro вообще без портала

Все они находятся в **Dashboard → Providers → Kiro**.

### Auto-Import (проще всего, если Kiro уже настроен)

Если у вас установлен Kiro IDE или `kiro-cli` и вы в нём входили, OmniRoute сам заберёт сохранённые данные (база `kiro-cli` и кэш `~/.aws/sso/cache`, на Windows `%USERPROFILE%\.aws\sso\cache`).

```
omniroute oauth start --provider kiro --import-from-system
```

Портал не открывается совсем — интернет нужен только самому шлюзу.

### Import Token

1. Возьмите refresh-токен Kiro (начинается с `aorAAAAAG…`) — например, из уже настроенного Kiro CLI/IDE.
2. Dashboard → Providers → Kiro → **Import Token**, вставьте токен.
3. Или через API:

```
curl -X POST http://localhost:20128/api/oauth/kiro/import ^
  -H "Content-Type: application/json" ^
  -d "{\"refreshToken\": \"aorAAAAAG...\", \"region\": \"us-east-1\"}"
```

(При заданном пароле на дашборд добавьте заголовок `Authorization: Bearer <management-ключ>` — как в разделе про API Key.)

### API Key

Долгоживущий ключ Kiro / CodeWhisperer (не refresh-токен). OAuth-сессии тут нет вообще, поэтому device-code и порталы ни при чём.

#### Куда именно вставлять ключ (пошагово)

1. Откройте **Dashboard**: `http://localhost:20128/dashboard/providers`.
2. Найдите карточку **Kiro** → кнопка **«Подключить»** (если Kiro уже добавлен, но подключений нет — кнопка добавления учётной записи на карточке).
3. В окне **«Подключить Kiro»** («Выберите ваш метод аутентификации») выберите **«API ключ»**.
4. Вставьте ключ в поле **«API ключ»** (вводится скрыто, как пароль). **«Регион AWS»** оставьте `us-east-1`, если только вы не создавали ключ в другом регионе.
5. Нажмите **«Проверить и сохранить API-ключ»** — OmniRoute тут же проверит ключ в AWS.

Что происходит дальше: подключение сохраняется как долгоживущий ключ (`authMethod: api_key`, без refresh-токена), в списке провайдеров появляется запись «API Key». Повторная вставка того же ключа **не создаёт дубликат** — OmniRoute узнаёт подключение по отпечатку и обновляет его. Проверить результат: `kiro-check` (должно быть ≥ 1 подключение Kiro) и кнопка «Тестовое соединение» на карточке Kiro.

Если при сохранении ошибка:

- «Invalid Kiro API key or AWS region» — ключ неверный или регион не тот, где создан ключ;
- «Failed to list profiles» или долгая «Проверка...» с таймаутом — сеть/прокси/антивирус не пускает к `codewhisperer.<регион>.amazonaws.com`; ключ при этом может быть рабочим.

#### Тот же шаг через API (необязательно)

```
curl -X POST "http://127.0.0.1:20128/api/oauth/kiro/api-key" ^
  -H "Content-Type: application/json" ^
  -d "{\"apiKey\": \"ваш_ключ\", \"region\": \"us-east-1\"}"
```

Ответ: `{"success":true,"connection":{...}}`. Если шлюз отвечает `401`/`403` — на дашборде задан пароль; в этом случае добавьте заголовок `-H "Authorization: Bearer <ключ с правом manage из Dashboard → API keys>"` или просто сделайте шаг через браузер.

## 6. Если Kiro не подключается совсем

Пока разбираетесь, работать можно и без Kiro:

- В **Dashboard → Providers** подключите другого бесплатного провайдера (например, **OpenCode Free** — без авторизации) или любой, для которого у вас есть ключ.
- Claude Code при этом запускается как обычно (`freeclaude`) — он ходит в локальный шлюз, а не в конкретного провайдера.
- Маршрутизацию настройте через **Combos** или модель `auto`.

---

## 7. Что собрать и прислать в чат

Если не получается — соберите и отправьте:

```
kiro-check --probe-kiro --json > kiro-check.json
omniroute logs > omniroute-logs.txt
omniroute --version
```

Полезно добавить: `omniroute providers list --json > providers.json` — видно, какие подключения Kiro сохранены; и скриншот ошибки.

`--probe-kiro` дописывает в отчёт сырые ответы Kiro на оба шага входа — по ним видно, дело в формате ответа, в истёкшем коде или в прокси.

Плюс напишите: какой способ подключения использовали (Device Code / Google / GitHub / Auto-Import / Token / API Key), какой браузер, что именно видите на экране (текст ошибки), и открывается ли ссылка с телефона. По этим данным причина находится быстро.
