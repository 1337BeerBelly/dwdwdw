# freeclaude — Claude Code через OmniRoute

Два инструмента в одном репозитории:

1. **freeclaude** — комплект для Windows: разворачивает локальный AI-шлюз **OmniRoute**, подключает бесплатный провайдер **Kiro AI** (модели Claude через AWS Builder ID) и запускает **Claude Code**.
2. **arena-pack / arena-unpack** — обмен файлами с чатом Arena: упаковать проект, отправить мне, получить правки обратно с бэкапом. Подробности — [docs/ARENA_BRIDGE.md](docs/ARENA_BRIDGE.md).

```
Claude Code  ->  http://localhost:20128/v1  ->  OmniRoute  ->  Kiro AI (Claude Sonnet / Haiku / Opus)
```

---

## Быстрый старт

1. Скачайте файлы этого репозитория в любую папку (или `git clone`).
2. Запустите **`install.bat`** — он скопирует скрипты в `C:\bat`, добавит папку в `PATH`, поставит всё нужное, поднимет шлюз и включит автозапуск.
   При первой установке Node.js может появиться запрос UAC — разрешите.
3. Откройте **новое** окно терминала, перейдите в папку проекта и выполните:

```
freeclaude
```

4. При первом запуске подключите провайдера: откройте <http://localhost:20128> → **Providers** → **Kiro AI** → **Add connection** → **Builder ID** → войдите через AWS Builder ID (можно через Google/GitHub) → подтвердите доступ. Затем запустите `freeclaude` снова.

Если ничего не устанавливать руками не хочется, дальше можно не читать — всё остальное в этом документе нужно для ручной настройки, тонкой подстройки и разбора проблем.

## Что делает `freeclaude.bat`

1. **Node.js** — ищет `node`. Если его нет или версия не поддерживается (нужна `22.22.2+` либо `24.x`–`26.x`), ставит LTS через `winget`.
2. **OmniRoute** — если пакета нет, выполняет `npm install -g omniroute`.
3. **Claude Code** — если `claude` не найден, ставит `winget install Anthropic.ClaudeCode`, а при неудаче — `npm install -g @anthropic-ai/claude-code`.
4. **Шлюз** — проверяет `http://127.0.0.1:20128/api/monitoring/health`; если сервер не запущен, поднимает его командой `omniroute serve --daemon --no-open` и ждёт готовности (до 2 минут).
5. **Провайдеры** — если не подключён ни один провайдер, открывает дашборд и показывает, что нужно сделать.
6. **Запуск** — `omniroute launch`, который сам подставляет Claude Code адрес шлюза и токен, и передаёт ему ваши аргументы.

Шлюз после выхода из Claude Code **не выключается** — он продолжает работать в фоне.

### Аргументы

```
freeclaude                        запустить Claude Code
freeclaude -p "объясни проект"    запрос без интерактива (аргумент уходит в Claude Code)
freeclaude --continue             продолжить прошлую сессию
freeclaude --dir C:\dev\my-app    сначала перейти в папку проекта, потом запустить
freeclaude --setup                только установить/проверить и поднять шлюз
freeclaude --version              версии Node.js, OmniRoute, Claude Code
freeclaude --help                 справка
```

Всё, что не является опциями самого `freeclaude`, передаётся в Claude Code без изменений: `freeclaude --model sonnet`, `freeclaude --resume` и т. д. (`freeclaude --help` показывает справку лаунчера, справка Claude Code — `claude --help`.)

### Переменные окружения

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `OMNIROUTE_PORT` | `20128` | Порт шлюза (меняется и в батниках, и в URL дашборда) |
| `OMNIROUTE_SERVER_HOST` | `127.0.0.1` | Адрес прослушивания. `0.0.0.0` — доступ с других устройств в сети |
| `REQUIRE_API_KEY` | не задано | `true` — требовать ключ OmniRoute для запросов к `/v1` |

## Ручная установка (если не пользуетесь `install.bat`)

Порядок соответствует оригинальной инструкции, но с исправлениями под актуальные версии (см. раздел «Что поправлено»).

### 1. Node.js

Нужна версия **22.22.2 и выше в ветке 22.x**, либо **24.x / 25.x / 26.x**. Node 24 удалять **не нужно** — OmniRoute её поддерживает.

Скачать: <https://nodejs.org/en/download> (ветка LTS). Проверка:

```
node -v
npm -v
```

Если Node установлен через установщик, после установки закройте и откройте терминал заново.

### 2. OmniRoute

```
npm install -g omniroute
```

Установка занимает 3–5 минут (тянутся зависимости дашборда). Предупреждения `npm warn ERESOLVE` и `deprecated` — нормальны, установку они не ломают.

### 3. Первый запуск шлюза

```
omniroute
```

Откроется дашборд <http://localhost:20128>. Мастер настройки можно пройти (рекомендуется задать пароль от дашборда), а можно сразу перейти к провайдерам. Пароль при необходимости сбрасывается командой `omniroute reset-password`.

Фоновый запуск без окна и без открытия браузера:

```
omniroute serve --daemon --no-open
```

Остановка: `omniroute stop`. Состояние: `omniroute status`, `omniroute health`, диагностика — `omniroute doctor`.

### 3.1. Дашборд OmniRoute — что это и зачем он открывается

**Дашборд — это не внешний сайт, а локальная панель управления на вашем компьютере:**
`http://localhost:20128`. Она живёт внутри самого шлюза OmniRoute, никуда данные не
отправляет и работает только когда шлюз запущен (его поднимает `freeclaude`).

Обычно в дашборде **ничего делать не нужно** — `freeclaude.bat` всё настраивает сам.
Он открывает эту страницу в браузере только в одном случае: если решит, что ни один
провайдер не подключён (тогда он показывает, где подключить Kiro). Проверить, так ли
это, можно командой `omniroute providers list`.

Если страница открылась, а подключение на месте (или она открывается каждый раз):

1. закройте вкладку и вернитесь в чёрное окно — Claude Code запускается там;
2. обновите комплект до **v1.6+** — в нём проверка провайдеров исправлена (см. §15 в
   [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md));
3. можно вообще запретить автооткрытие: выполните `set FREE_CLAUDE_NO_DASHBOARD=1`,
   а затем `freeclaude`.

Что полезного есть в дашборде (по желанию):

- **Провайдеры** — карточка Kiro: статус подключения, кнопка «Тестовое соединение»,
  добавить/удалить второй аккаунт;
- **Аналитика и логи** — что и куда уходит, сколько запросов, какие ошибки;
- **Настройки** — прокси, ключ доступа к `/v1`, пароль на сам дашборд;
- **Комбо** (`Combos`) — правила маршрутизации между провайдерами, выбор модели `auto`.

Пароль на дашборд по умолчанию не задан (шлюз слушает только `127.0.0.1`) — ставить
его имеет смысл, если вы открываете доступ с других устройств.

### 3.2. Какая модель запрашивается

Claude Code по умолчанию просит модель без префикса (`claude-sonnet-4-6`), а у Kiro имена
другие — `claude-sonnet-4.5`, `claude-sonnet-5`, `claude-haiku-4.5`. Пока в шлюзе подключён
один провайдер, ошибок обычно нет; если подключение не одно, OmniRoute может ответить
`400 Ambiguous model`. Тогда модель называют явно, с префиксом Kiro:

```
freeclaude --model kr/claude-sonnet-4.5
```

или навсегда — в `%USERPROFILE%\.claude\settings.json`:

```json
{
  "env": {
    "ANTHROPIC_MODEL": "kr/claude-sonnet-4.5",
    "ANTHROPIC_SMALL_FAST_MODEL": "kr/claude-haiku-4.5"
  }
}
```

Префикс `kr/` нужен **обеим** переменным: без него фоновая модель снова упрётся в
`400 Ambiguous model`, когда подключений несколько. Если в списке несколько подключений
Kiro — оставьте одно рабочее («Тестовое соединение» на карточке Kiro).

Разбор — §17 в [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md).

### 4. Провайдер Kiro AI

В дашборде: **Providers** → **Kiro AI** → **Add connection** → **Builder ID**. Откроется страница авторизации AWS Builder ID — вход по Google/GitHub или по e-mail, затем подтверждение доступа.

Kiro AI отдаёт модели Claude (Sonnet / Haiku / Opus) в рамках бесплатного тарифа провайдера (порядка 50 кредитов в месяц на аккаунт). Язык интерфейса дашборда переключается в правом верхнем углу.

Вход устроен как device-code: окно авторизации показывает код и ссылку, а шлюз сам ждёт подтверждения. Поэтому ссылку можно открыть **на телефоне** и ввести код там — это выручает, когда портал не открывается на компьютере. Если совсем не выходит, Kiro подключается и без портала: Auto-Import из Kiro CLI/IDE, Import Token или API Key (ключ вставляется в **Providers → Kiro → «API ключ» → «Проверить и сохранить API-ключ»**; на дашборде может быть список «Счета» — добавление учётной записи там же). Диагностика — `kiro-check`, при ошибке «Connection Failed / invalid_token_response» — `kiro-check --probe-kiro`; при 429 «Budget has been exceeded» или 400 «Ambiguous model» — `kiro-check --test-call` (§16 и §17 в [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md)); подробности — [docs/KIRO_TROUBLESHOOTING.md](docs/KIRO_TROUBLESHOOTING.md).

### 5. Ключ доступа (необязательно)

**Endpoints** (в старых версиях — **API Manager**) → **Create key** → задать имя (например, `code`) → сохранить значение сразу: повторно его не покажут.

Для работы **на этой же машине** ключ не обязателен: `omniroute launch` подставляет заглушку, а локальный шлюз без включённого `REQUIRE_API_KEY` её принимает. Ключ нужен, если вы включили `REQUIRE_API_KEY=true` или ходите в шлюз с другого устройства.

Лаунчер умеет брать ключ из файла — положите его одной строкой в:

```
%USERPROFILE%\.freeclaude\apikey.txt
```

### 6. Claude Code

```
winget install Anthropic.ClaudeCode
```

Альтернатива (устаревший, но рабочий способ): `npm install -g @anthropic-ai/claude-code`.

Проверка: `claude --version`. Если команда не находится, а файл `%USERPROFILE%\.local\bin\claude.exe` существует — добавьте `%USERPROFILE%\.local\bin` в `PATH`. Батники это делают сами.

### 7. Папка `C:\bat` и `PATH`

Создайте `C:\bat`, положите туда файлы комплекта и добавьте папку в `PATH` пользователя (Параметры → Система → О системе → Дополнительные параметры системы → Переменные среды). После этого `freeclaude` работает из любого терминала.

Именно это автоматизирует `install.bat`.

### 8. Запуск

```
freeclaude
```

Схема работы: OmniRoute держит шлюз в фоне (`omniroute serve --daemon`), а Claude Code получает `ANTHROPIC_BASE_URL=http://localhost:20128` и токен и уходит не в Anthropic, а в ваш шлюз.

## Автозапуск, остановка, обновление

```
omniroute autostart enable      включить запуск шлюза при входе в Windows
omniroute autostart status      проверить состояние
omniroute stop                  остановить шлюз
npm install -g omniroute@latest обновить OmniRoute
claude update                   обновить Claude Code (нативная установка)
```

То же самое через батники: `freeclaude-status` (флаг `--open` дополнительно открывает дашборд), `freeclaude-stop`, `freeclaude-update`, а также `freeclaude-status --autostart-on` / `freeclaude-status --autostart-off`.

Автозапуск реализован через `.vbs`-скрипт в папке «Автозагрузка» и не требует прав администратора.

## Работа над вашими файлами вместе с Arena

Инструменты `arena-pack` / `arena-unpack` позволяют делать то, чего freeclaude не умеет: отправлять мне свой проект и получать правки обратно.

```
arena-pack C:\dev\my-app            упаковать проект (спросит задачу)
   ↓  прикладываете zip в чат Arena
   ↓  я правлю файлы и возвращаю архив
arena-unpack reply.zip              разложить правки (бэкап делается автоматически)
```

- Секреты (`.env`, ключи, `credentials.json`) в отправляемый архив не попадают, служебные папки (`node_modules`, `.git`, `dist`) — тоже. Отчёт печатает каждое исключение.
- Перед записью файлов делается бэкап в `<проект>\_arena_backup\<пакет>\` — откат в одну команду копирования.
- Ничего не перезаписывается «на веру»: сравнение идёт по SHA-256, неизменённые файлы не трогаются.
- Если проект уже в GitHub — архивы не нужны: скажите ссылку, я буду коммитить в ветку, вы забираете через `git pull`.

Полное руководство: [docs/ARENA_BRIDGE.md](docs/ARENA_BRIDGE.md).

## Безопасность

- **Шлюз — это ваши ключи и квота.** OmniRoute по умолчанию слушает `0.0.0.0` и не требует ключа для `/v1`. В локальной сети это означает, что любой, кто дотянется до порта, сможет жечь вашу квоту. Комплект по умолчанию прописывает `OMNIROUTE_SERVER_HOST=127.0.0.1` (файл `%USERPROFILE%\.omniroute\.env`), то есть шлюз доступен только с этой машины.
- Нужен доступ с телефона или другого компьютера — уберите эту строку и задайте `OMNIROUTE_SERVER_HOST=0.0.0.0`, а также включите `REQUIRE_API_KEY=true` и создайте ключ в дашборде.
- Секреты и база шлюза лежат в `%USERPROFILE%\.omniroute` (`storage.sqlite`, `.env` с ключом шифрования). Не выкладывайте эту папку никуда.
- Пароль от дашборда восстанавливается через `omniroute reset-password`.

## Что поправлено относительно исходной инструкции

| В инструкции | Как на самом деле |
| --- | --- |
| «Удалите Node.js, если версия новее 22 (например, 24)» | Не нужно. OmniRoute 3.8.51 требует `>=22.22.2 <23` **или** `>=24.0.0 <27`, то есть Node 24 подходит |
| «Kira AI» | Провайдер называется **Kiro AI** |
| «Сразу сохраните ключ — потом нельзя посмотреть» | В актуальных версиях ключ можно посмотреть и отозвать (`omniroute keys`, раздел **Endpoints**), но сохранить его сразу — по-прежнему хорошая привычка |
| «Пропишите команду `omniroute` — запустится локальный сервер» | Верно, но для фонового режима используйте `omniroute serve --daemon --no-open`, иначе сервер закроется вместе с окном терминала |
| «Запускайте `.bat` вручную из папки» | Батник можно ставить в `C:\bat` и запускать откуда угодно — этим занимается `install.bat` |
| «Улучшенный батник» (в тексте отсутствует) | Реализован как `freeclaude.bat`: доустановка компонентов, ожидание готовности шлюза, автозапуск провайдера-проверки, проброс аргументов |

## Ограничения

- **Claude Desktop** (десктопное приложение) на шлюз переключить нельзя — Anthropic не даёт в нём переопределять адрес API. Работает именно CLI, то есть Claude Code.
- Бесплатный доступ идёт через тарифы сторонних провайдеров: лимиты, доступность моделей и условия использования меняются, и их стоит проверять самостоятельно. Комплект лишь настраивает связку локально.
- OmniRoute — сторонний проект (MIT), не связанный ни с Anthropic, ни с AWS. После установки обновляйтесь командой `npm install -g omniroute@latest`.

Частые ошибки и их решения — в [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md).
